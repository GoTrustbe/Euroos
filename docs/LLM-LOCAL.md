# On-device inference on EuroOS

A language model runs on EuroOS itself, in a sandboxed glibc process, with no
network and no cloud. Proven 2026-10-09 ([llm-local]): "The capital of
Belgium is" → "the largest city in", generated by SmolLM2-135M (Q8) on the
EuroOS kernel under QEMU, identical to the same engine on the host.

## How it is put together

- Engine: llama.cpp `llama-simple`, built in an Ubuntu 24.04 container so it
  links against the glibc 2.39 EuroOS bundles, without AVX/FMA/F16C/SSE4.2
  (runs under `-cpu qemu64` and on any x86-64) and without OpenMP.
- Model: a GGUF file. The demo pack carries SmolLM2-135M-Instruct Q8_0
  (145 MB); any GGUF works, memory permitting.
- Delivery: both files in a signed EuroPack (`scripts/build-llm-pack.sh`),
  attached as a virtio disk. The kernel verifies the manifest signature and
  every page it reads against the per-file Merkle leaf table; the model is
  demand-paged straight from the pack, never copied whole into RAM.
- Runtime: `llm <prompt>` in the Terminal (`kernel/src/llm.rs`). The engine
  runs through the Linux-ABI bridge as a sandboxed process: console, file
  and process-info capabilities only, no network capability at all.

## Honest limits

- Speed under QEMU TCG is tens of seconds per token (scalar SSE2, software
  CPU); the boot self-test asks for 4 tokens and takes about 4 minutes. On
  real hardware (KVM, the NUC) the same engine runs at normal llama.cpp
  speed for its size. This is a proof of the path, not a usable assistant
  yet.
- 135M parameters is a demo model: it completes text, it does not reason.
  A 1 to 3B model at Q4 fits the 8 GB laptop class EuroOS targets; that is
  the next step, on hardware.
- Not yet wired to EuroAgent: the agent runtime still reaches an
  Ollama-compatible endpoint over EuroNet. Pointing its local backend at an
  on-device engine (a llama-server equivalent behind the MCP gateway) is the
  follow-up.
- The pack must be a virtio disk. Attached as AHCI it is not scanned for a
  pack; the AHCI "blank disk" write self-test now refuses any disk that
  holds data, after it overwrote a pack's leaf table during this work.
